# RiceWine Linux acceptance checklist

These are **manual tests to run on a real Linux desktop**, not tests that CI claims to have completed. Run on both X11 and Wayland, then repeat essential paths in the macOS, XP Luna Blue and Windows 10 styles. Note the distro, Wine/Proton versions, display server and graphics driver for every failure.

The maintainer will perform the **manual user acceptance at the 1.0 gate**, not after each development milestone. Automated unit/integration/security checks remain required during development; no untested desktop behavior is marked as accepted.

1. **Startup and availability:** Start RiceWine with system Wine installed and without it. Verify the missing-runtime diagnostic, button states, keyboard navigation and safe exit.
2. **EXE install:** Install a known trustworthy Windows EXE in a new prefix. Confirm the installer opens, logs are written, Choose launch EXE works, and Play actually starts the application.
3. **MSI install:** Install a compatible MSI and confirm its parameters arrive intact without a shell. Launch its resulting application.
4. **Portable EXE:** Register a portable program, verify the prefix is initialized (or prepared for Proton on first run), launch, exit and relaunch it.
5. **Custom Wine:** Choose a separately installed Wine executable with a sibling wineboot. Verify that runner, not system Wine, is used to initialize and launch the prefix.
6. **Proton/umu:** With umu-run and a Proton directory available, install/run a compatible EXE, verify GAMEID/PROTONPATH/WINEPREFIX, then inspect the log. MSI-via-Proton and Winetricks-on-Proton must explicitly explain their limitation.
7. **Winetricks:** Apply a component deliberately on a disposable prefix; success and failure both produce useful status and logs. DXVK/VKD3D availability depends on the installed Winetricks release and the Vulkan driver.
8. **Import:** Register an existing disposable Wine prefix. Confirm files and the original path are unchanged. Removing the library entry must never delete the prefix.
9. **Backup/restore:** Close Windows processes, back up a prefix, alter a test file, restore it, and verify the original is untouched while the restored program has a new prefix and the original file content.
10. **Application menu and Open With:** Add a per-program shortcut, run it while the GUI is already open, register the opt-in EXE/MSI handler, and verify clicking an EXE only opens a **pre-filled setup dialog**. Check that desktop MIME defaults did not change.
11. **Appearance:** Switch all three maintained Rices (macOS, XP Luna Blue and Windows 10), restart and check focus, contrast, list selection, settings, dialogs and keyboard navigation. Test desktop following for Luna/WhiteSur/Windows10/Fluent, unknown-theme fallback, and legacy preferences (Windows 10 variants map to Windows 10; Luna Olive/Silver map to Luna). Verify at 780×500 that the macOS toolbar, sidebar, status bar and dialogs remain reachable and that the compositor's native titlebar is unchanged.
12. **Recovery and performance:** Interrupt an installer, supply a corrupt runner profile/catalog in a **throwaway test data directory**, retry, and check no data was silently removed. Measure idle RSS and startup time on both the ThinkPad and a lower-power machine.
13. **1.0 library workflows:** Add 30 programs, search by name, rename an entry, restart, and verify renamed owned menu shortcuts. Scroll through a larger synthetic catalog and confirm only visible rows are rendered. Check keyboard navigation when search returns no results.
14. **1.0 launch overrides:** Set arguments containing spaces and environment overrides, verify the exact values reach a trusted test EXE, restart and confirm persistence. Reject disallowed variables (especially `WINEPREFIX` and `LD_PRELOAD`), duplicate variables and oversized inputs without changing the prior profile.
15. **1.0 discovery and diagnostics:** Choose an installed Proton from Steam discovery, handle absent/removed Proton gracefully, and compare `--list`, `--diagnose`, `--verify-library` with the GUI. Ensure read-only CLI commands work while the GUI is open.
16. **1.0 metadata recovery:** Use `--snapshot-library` and Settings to capture metadata while the GUI runs. Confirm both catalog and preferences are copied, no prefix content is copied, and no live data is changed. Practice a manual restore only on a separate disposable data directory before attempting real recovery.
17. **1.0 Open With handoff:** Keep RiceWine open, invoke `ricewine --install-file /absolute/path/setup.exe` from another terminal and confirm the existing GUI (not a second broken instance) displays a reviewable install draft. Repeat while the first draft remains open: the second request should queue. Check that shutdown removes the private socket and restarting works.
18. **1.0 installation and recovery:** Run `sh scripts/install-user.sh` twice. Confirm the second installation makes a unique backup, the menu launcher starts the current executable, and an interrupted or failed registration does not replace the previous working executable. Check that symbolic-link executables are refused.
19. **1.0 uninstall:** Run `sh scripts/uninstall-user.sh`, confirm only the installed executable and RiceWine-owned desktop entries disappear, then inspect the prefix, settings, logs and backup directories to verify they were preserved. Reinstall and confirm the catalog is intact.
20. **1.0 candidate checks:** Confirm a clean-clone build, local `cargo fmt/test/clippy/doc`, GitHub Actions checks, dependency/secret review, release notes, correct package version and a maintainer-approved license before creating any stable tag.

### 2.0 manual acceptance extension

21. **Installation cancellation:** Start a real Windows setup, cancel with confirmation, verify that the installer exits, UI unlocks, logs remain and the partial prefix is preserved. Repeat during Wine prefix initialization.
22. **Executable discovery:** Install programs with unique, multiple and no launch EXEs; confirm only unambiguous results are selected, uninstallers are excluded and the manual override works.
23. **Play/Stop:** Start a real graphical EXE, stop it with confirmation, confirm its process closes and other programs/prefixes stay intact. Retest launching afterward.
24. **Storage:** Compare the displayed disk usage with `du`, create old/new temp files in a disposable owned prefix, preview cleanup and confirm only eligible old files disappear. Imported prefix cleanup must be unavailable.
25. **Presets:** Apply each of the five profiles, save and relaunch a disposable app. Confirm arguments are preserved and the exact allowlisted environment reaches the runner.
26. **GE-Proton management:** Fetch latest release metadata, download and verify the official tarball, start a compatible EXE using `umu-run`, cancel an in-progress download, then remove an unused managed build. A build referenced by any app must not be removable.
27. **Updates:** Configure a genuine public GitHub `owner/repo`, retrieve the latest release, open its upstream page and run a trustworthy publisher update EXE/MSI in the existing prefix. Confirm catalog ID, prefix path and backups are preserved. Invalid repositories and failed fetches should show useful errors.
28. **2.0 usability/performance:** Use keyboard-only navigation through new actions, verify confirm/cancel and disabled states under Luna Blue, inspect text clipping at 780×500 and measure UI responsiveness during scans/downloads. Repeat functional paths under macOS and Windows 10; none of the Rices may change system window decorations. Verify cached runner status updates after Save runner, selection changes, and pressing Refresh profiles following an external TOML edit.

29. **Windows 10 visual fidelity:** Verify Settings-style sidebar/navigation, active selection rail, search and the inline app-details workflow on an interactive X11 and Wayland desktop. Test at 780×500 and 1080×700, with keyboard focus. Compare fresh source screenshots and confirm XP/macOS rendering was not altered. Do not count empty-library screenshot generation as proof of a populated-list experience.

30. **Guided setup and errors:** Install with browse, drag-and-drop, and Open With; none may autoexecute the dropped file. Verify filename-derived name suggestions and that user edits persist when choosing another file. Submit invalid data and missing Wine/custom runner configuration and confirm errors appear *inside* the still-open dialog with all fields intact.
31. **Quick first run:** After installing/importing while a search filter is active, confirm the new program is selected and visible. Test ambiguous, empty and large EXE scans: the UI must stay responsive, busy state must clear on success/error, and picking a suggested EXE must enable launch. A manual picker must remain available.

32. **3.0 personal workspace:** Upgrade an existing 2.x library without migrating applications.json or prefix data. Mark a program as favorite, restart, switch All/Favorites filters and Name/Recent sort, successfully launch it, then verify Recent order. A failed launch must not be recorded. Check empty favorites, large catalogs, and removal of a favorite.
33. **3.0 read-only doctor:** With a good Wine prefix, missing EXE, missing prefix and a corrupted runner TOML, run Settings → Health & diagnostics and ricewine --doctor. Confirm actionable findings and that **no files change**. Unavailable system Wine must not invalidate unrelated Proton profiles. Confirm the GUI stays responsive while checking.

Release blockers: crashing/blocked UI, data loss, unsafe prefix or runner removal, failed backup restore, broken launcher integration, an unapproved license, or any confirmed Wine/Proton command that launches the wrong runner. Keep real Windows programs out of CI and never treat a mock Wine binary as hardware acceptance.
