# Changelog

All entries describe source-code milestones, not automatic confirmation of real Windows app compatibility.

## Unreleased – simpler install, import and first run

- Guide installations through file selection, automatic app-name suggestion and the default Wine setup; preserve edited names and show validation errors inside the dialog without discarding inputs.
- Support drag-and-drop EXE/MSI to prefill the existing installation review, never to auto-run Windows code.
- After install or import, clear stale search filters and reveal the newly registered app in the Library.
- Offer direct automatic EXE discovery and manual selection when a program has no launch file; move the bounded filesystem scan into a worker thread to keep egui responsive.
- Keep the three approved visual themes, permissions, safety confirmations and Wine/Proton execution paths intact. Real-desktop acceptance remains outstanding.

## Previous development – Windows 10 Settings fidelity overhaul

- Rework the Windows 10 Rice from a generic dashboard layout to the Apps & features interface of Windows 10 Settings (1809–1909): neutral side navigation, blue selected rail, page-level app actions and native-sized type.
- Draw distinct 63px app list rows with local window glyphs, two lines of app/runner information and readable status; preserve virtualized scrolling and the cached runner profiles.
- Move selected-program actions into a full-width section below the list instead of a right-side card. Install, import and Rice selection follow the same flat control hierarchy.
- Keep macOS, XP Luna and all Wine/Proton workflows unchanged. Real Linux screenshots are regenerated by CI; interactive Wine/Proton tests remain an explicit acceptance requirement.

## Previous development – Windows 10 Rice and lighter library rendering

- Add a dedicated Windows 10 style alongside XP Luna Blue and macOS. Flat navigation, a new apps view, a compact status/list layout and a primary installation action use native egui controls while leaving Linux window decorations untouched.
- Make legacy Windows 10 appearance names round-trip to the unified Windows 10 Rice. Luna Olive/Silver preferences still migrate to Luna Blue.
- Load per-program Wine runner profiles once and cache them while rendering; refresh automatically when selecting a program or saving its runner, or manually after changing TOML files outside RiceWine. This eliminates repeated profile filesystem I/O from visible program rows and selected-program details.
- Expand real Xvfb screenshot capture to all three Rices and add a Windows 10 gallery. Automated UI capture is not real Wine/Proton compatibility testing.

## Previous development – curated Rices and macOS interface

- Add a Finder-inspired macOS application shell with dedicated navigation, toolbar, program list and status surfaces. The Linux compositor remains responsible for native window borders.
- Retire the incomplete Windows 10 Light/Dark and XP Luna Olive/Silver experiments at this stage; the previous picker contained two Rices. Windows 10 later returned as a newly implemented single maintained Rice.
- At this milestone saved legacy appearance names were mapped to Luna Blue. The subsequent Windows 10 Rice now restores mapping for the Windows 10 aliases without touching program or prefix data.
- Update user documentation and manual desktop-acceptance coverage; visual and functional acceptance on real X11/Wayland systems remains outstanding.

## Previous development – XP Luna Blue application UI overhaul

- Replace the Luna-only interior with functional full-width Explorer menus and navigation, classic shaded task panes, compact forms, original XP-era-style icons and coherent focus/hover/pressed states; preserve OS-owned window decorations.
- Rework Library details, Prefix backup/cleanup, Wine/Proton runner diagnostics and settings into grouped management surfaces while retaining all existing operations and guards.
- Rebuild install/import and confirmation dialogs with consistent classic controls and centered windows.
- Add isolated screenshot coverage for all four pages and both setup dialogs, plus a safe on-demand Rust formatting workflow. Actual Wine/Proton and desktop acceptance remains separate from automated rendering.

## 2.0.0-beta.1 – guided application lifecycle

- Cancel long-running installations and update installers; stop a tracked Windows application with an explicit warning. Prefixes are never deleted during cancellation.
- Bounded scan for installed EXEs, with automatic selection only for an unambiguous candidate and manual override for other applications.
- Per-prefix disk usage and opt-in preview/cleanup of temporary files older than seven days. Cleanup is blocked for external/imported prefixes and never follows symlinks.
- Five allowlisted Wine launch presets, selectable from the existing Runner UI without modifying launch arguments.
- Discover Steam Proton builds; fetch the latest official GE-Proton release, verify its SHA512 checksum, install it user-locally and explicitly remove unused managed releases. Download is cancellable; existing builds are never replaced.
- Configure optional GitHub release checks and a manually labeled installed version for supported Windows apps; run trusted EXE/MSI updates in the existing prefix after confirmation.
- Add focused tests for cancellation, installer argument integrity, executable discovery, data deletion boundaries, release parsing and release asset verification. No hardware compatibility acceptance is implied.

## 1.0.0-rc.3 – built-in Rice collection

- Add Windows 10 Dark, XP Luna Olive and XP Luna Silver to the existing Windows 10 Light and XP Luna Blue styles.
- Apply coherent palette tokens to panels, navigation, buttons, inputs and selection states; add keyboard-accessible preview buttons in Settings.
- Render the app inside a theme-colored central panel instead of exposing the renderer's black clear color; fix strong-label and dark-mode error-message contrast.
- Persist all five Rices without changing previously stored `windows10`/`luna` preferences. Manual selection disables automatic desktop matching.
- Test palette text/selection contrast and serialization of every appearance; no Wine or prefix execution paths changed.

## 1.0.0-rc.2 – preparing maintainer acceptance

- Use private permissions even for existing RiceWine data roots, and reject a symlinked data root before writing.
- Install binaries through a staged replacement, refuse unrelated existing binaries, restore the old executable on registration failure and add a safe per-user uninstaller. The uninstaller removes only owned desktop shortcuts and never deletes prefix or catalog data.
- Add automated install/uninstall/rollback tests and shell-script syntax checks.
- Pin CI actions to verified upstream commit SHAs, restrict workflow permissions, and allow manual workflow dispatch.
- Restore coherent 1.0 release-candidate versioning; no stable tag or GitHub Release has been published.

## Pre-1.0 compatibility hardening

- Reject unsupported or invalid runner profiles before creating a Wine prefix.
- Build Winetricks commands separately so exact Wine binary, prefix and DXVK/VKD3D verbs can be regression-tested.
- Add a Proton/umu CLI integration test using a disposable fake runner, including paths with spaces and explicit game IDs.
- Keep manual user acceptance at the 1.0 release gate.
